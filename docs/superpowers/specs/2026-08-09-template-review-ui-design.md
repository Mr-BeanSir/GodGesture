# Template Review UI Design

## Purpose

Task 8 and Task 9 provide two focused review surfaces:

- Desktop export: confirm the package metadata, targets, risks, and required official plugins before either saving locally or submitting to the official public directory.
- Web Console moderation: inspect an immutable submitted version and choose a moderation state without editing its content.

Both surfaces use the same vocabulary and display the server as the authority for author identity, risks, plugin availability, and quota limits.

## Visual Direction

GodGesture is an input instrument, so the review UI uses a quiet control-room surface with one signal color reserved for risk and status. Existing Element Plus tokens remain the base; no new framework or raw global theme is introduced.

- `#161A1D` graphite surface for dense dark panels
- `#20262B` raised surface for grouped metadata
- `#E7ECEF` primary text
- `#9AA7AE` secondary labels and timestamps
- `#5CC8A1` approved/safe state
- `#F0B35A` pending and caution state
- `#E56B6F` rejected/high-risk state

Typography stays with the existing system UI stack. Page titles use the current compact heading scale; metadata uses 12px labels and 13-14px values; hashes, UUIDs, and command snippets use a monospace face. The visual signature is an eight-direction gesture motif used only as a small status marker beside the immutable version identity, never as decoration.

## Desktop Export Review

The export dialog keeps local JSON export and public submission as separate actions. The public action is rendered only when the account is signed in to the official endpoint with a verified email.

```text
┌─────────────────────────────────────────────────────┐
│ Export gesture template                         ×  │
│ title / summary / tags                              │
├───────────────────────┬─────────────────────────────┤
│ target selection       │ review                       │
│ groups + apps          │ targets, gesture count       │
│ search / select all    │ risks and plugin IDs         │
│                       │ quota + moderation notice    │
├───────────────────────┴─────────────────────────────┤
│ Cancel       Export JSON       Submit to public dir │
└─────────────────────────────────────────────────────┘
```

Review content is plain Vue interpolation. Author is read-only and resolved automatically; no slug, version, repository, or author inputs exist. The neutral filename is generated by the export utility and never includes title text.

## Web Console Moderation

The page is a three-zone control surface: queue, immutable version detail, and actions. On narrow screens the zones become queue -> detail -> action sections in document order. Queue rows are keyboard-focusable and preserve selection while the detail view loads.

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ queue        │ immutable version detail     │ actions      │
│ status/risk  │ title, summary, author        │ approve      │
│ submittedAt  │ targets/intents/commands     │ reject       │
│              │ risks/plugins/hash/size      │ suspend      │
│              │ review + report history      │ restore      │
└──────────────┴──────────────────────────────┴──────────────┘
```

Actions require a reason where the server contract requires one. No control mutates title, summary, package bytes, author, or server-computed risks. Status badges use the existing semantic colors: pending amber, published green, rejected/suspended red, and withdrawn neutral.

## Accessibility and States

- All queue rows, tabs, and action buttons have visible keyboard focus and text labels.
- Loading, empty, network error, and missing-version states each retain an actionable next step.
- Reduced-motion users receive no animated transitions.
- Long title/summary content wraps inside bounded regions; hashes and command values wrap or scroll without changing the layout width.
- User content is never rendered with `v-html`.

## Verification

- Desktop tests cover gating, author resolution, neutral filenames, risk/plugin summary, local export, and public submission error states.
- Web Console tests cover queue selection, immutable detail rendering, required reasons, state transitions, report resolution, and non-admin denial.
- Typecheck and production builds run for Desktop and Web Console; API generation remains in sync.
