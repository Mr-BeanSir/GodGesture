# 手势模板列表卡片化美化设计

## 目标

改善 Desktop 手势模板库的目录列表可读性和视觉层次，让用户更容易扫描标题、摘要、标签、风险状态和作者信息。

本次只改变模板列表的呈现方式，不改变模板数据、风险协议、详情页、采纳逻辑或列表的交互行为。

## 现状与问题

`apps/desktop/src/views/TemplatesView.vue` 当前使用连续的无边框按钮和底部分隔线呈现模板目录。标题、摘要、标签和右侧元信息虽然都存在，但列表缺少清晰的条目边界和卡片层次，在浅色/深色主题下扫描成本较高。

目录条目的风险徽章当前按统一状态渲染。本次明确保留该行为，不拆分风险类型，也不改变 `entry.risks` 的协议或 Store 处理。

## 方案比较

### 方案 A：保留纵向列表并卡片化（采用）

- 每个模板条目保留为一个语义 `<button>`，继续整行点击打开详情。
- 使用独立边框、圆角、内边距和条目间距形成卡片边界。
- 保留现有两列信息结构：左侧标题/版本、摘要、标签；右侧统一风险徽章和作者。
- 增加克制的悬停背景、边框变化和键盘焦点反馈。

优点是改动范围小、信息密度和纵向扫描方式不变，适合 Desktop 固定设置窗口，也不会引入新的业务字段或响应式分支。

### 方案 B：密集型信息列表

继续使用连续分隔线，仅重排字号、间距和右侧元信息。实现风险最低，但条目之间仍缺少独立视觉边界，整体提升有限。

### 方案 C：双列模板卡片

将目录改为两列卡片以提高空间利用率。它会压缩摘要和作者信息，并改变当前固定窗口中的纵向浏览节奏；对当前模板数量和内容长度没有足够收益，因此不采用。

## 详细设计

### 结构与数据

- 保持现有 `v-for`、`key`、`aria-label` 和点击事件。
- 不修改 `GestureTemplateCatalogEntry`、模板 Store、API 或风险字段。
- 不新增下载次数、风险类型拆分、状态筛选或其他目录信息。
- 保留现有的统一风险徽章渲染。

### 视觉层级

- `.templates-view__list` 由连续分隔线列表调整为带条目间距的列表容器。
- `.templates-view__row` 使用项目现有 `--gg-*` 设计 token 设置边框、圆角、表面色和间距。
- 标题与版本徽章继续作为第一层信息；摘要使用现有弱化文本；标签保持紧凑换行。
- 右侧元信息维持固定视觉列宽，作者与风险徽章保持右对齐，避免左侧内容变化导致信息跳动。
- 悬停状态只做轻量表面和边框变化；`:focus-visible` 保留清晰的主题 ring，不移除键盘可见焦点。

### 可访问性与平台边界

- 保持语义按钮，不改为带点击事件的 `div`。
- 保持现有 `aria-label` 与整行点击行为。
- 保持 Desktop 固定窗口布局，不新增 Web Console 的响应式断点。
- 使用现有主题 token，确保浅色/深色模式不引入硬编码颜色。

## 实施范围

预期只修改：

- `apps/desktop/src/views/TemplatesView.vue`
- 对应的 Desktop 模板视图 focused 测试（仅在现有测试缺少可观察断言时补充）

本次不修改 `packages/shared`、模板 Store、API、详情页风险逻辑或现有滚动条改动。

## 验收与验证

- 模板目录仍能显示标题、版本、摘要、标签、统一风险徽章和作者。
- 点击任意条目仍能打开详情，键盘 Tab 聚焦和 Enter/Space 激活路径保持可用。
- 条目之间具有独立卡片边界，悬停和键盘焦点状态清晰。
- 样式只使用现有 `--gg-*` token，不产生页面级横向溢出。
- 运行 Desktop 模板视图 focused 测试，并执行 `git diff --check`；不运行与本次无关的全仓验证。
