# 手势模板行与账户登录界面设计

日期: 2026-08-03

## 范围

本次只调整 Desktop Vue 中两个现有页面的视觉表现:

1. 手势模板列表行在浅色主题下使用纯白表面,不再透出页面灰色画布。
2. 账户与同步页面的未登录状态重组为与工作台一致的身份区,降低登录表单的突兀感。
3. 保留现有登录、注册、OAuth、错误、加载、回车提交和重试行为,不改变认证或同步协议。

## 手势模板列表

`.templates-view__row` 使用共享的 `var(--gg-surface)` 作为默认背景。该 token 在浅色主题中
为纯白,在暗色主题中为现有深色表面,避免强制白色导致暗色主题下的文字和边框失去对比度。
列表顶部与行间分隔线、键盘焦点和 hover 反馈继续沿用现有 token。hover 只提供轻微的填充
变化,不改变行尺寸或列表滚动位置。

## 未登录身份区

未登录状态继续位于“账户与同步”页的唯一滚动区,并与登录后的账户概览和配置快照使用同一
最大宽度。页面不再显示左上角孤立的窄登录卡片。

身份区使用一个 `gg-section` 外层,内部不嵌套卡片:

- 顶部身份说明行包含账户图标、登录标题和同步说明,形成清晰但克制的状态入口。
- 内容区在宽窗口下分为两列。左列承载登录/注册分段选择、邮箱、密码、注册密码要求和主提交
  按钮；右列承载第三方登录。
- 两列之间使用细分隔线,不使用额外边框、阴影、渐变、插画或营销式说明。
- 第三方 provider 可用时显示现有 provider 按钮；加载时显示紧凑 skeleton；不可用时显示内联
  次级状态和重试按钮,不再使用占据整列的大块灰色 alert。
- 认证错误保留明确的错误样式,置于身份说明和认证内容之间,不会改变表单字段的相对位置。
- 登录/注册切换继续使用分段控件；主操作文案、autocomplete、密码可见切换和 Enter 提交保持
  原行为。

在窄布局下,内容区改为单列,分隔线由竖向改为横向。所有控件保持稳定宽度,不出现横向滚动、
文字截断或按钮挤压。最低 800x560 窗口仍由页面唯一滚动区承担垂直溢出。

## 主题与文案

- 浅色主题的模板行和身份区均使用纯白工作台表面；暗色主题使用现有深色 token。
- 颜色只使用现有 GodGesture/Element Plus token,不增加单色大面积装饰或主题专属硬编码覆盖。
- 新增的可见文案和无障碍文本必须同时加入 `zh-CN` 与 `en` vue-i18n 消息；组件不得硬编码
  中文。
- 图标使用现有 Element Plus 图标库,图标不单独表达认证状态,文字仍提供完整含义。

## 状态与错误处理

本次不修改账户 store。以下状态继续由现有 store 驱动:

- `initializing` 和 `sessionError` 保持现有功能,视觉上继续服从页面工作台宽度。
- `signedOut` 使用新的身份区布局。
- 已登录态的账户信息、同步按钮、退出登录和配置快照保持原结构与行为。
- `authBusy` 同时阻止重复密码提交和 OAuth 操作；provider 加载失败仍可主动重试。

## 测试与验收

- Desktop 定向前端测试、typecheck 与 production build 通过。
- locale key parity 和账户消息编译测试通过。
- 在 980x700 与 800x560 下检查中文/英文、浅色/暗色主题。
- 检查登录和注册模式、provider 加载/可用/不可用、认证 pending/error 状态。
- 检查模板列表默认背景、hover、键盘焦点和滚动区域,浅色背景为纯白且暗色不出现白色行。
- 检查页面不存在横向溢出、嵌套卡片、文字遮挡或动态状态导致的明显布局跳动。

## 非目标

- 不修改 Server、OAuth provider 配置、凭据存储、同步时序或快照行为。
- 不新增忘记密码、验证码、账户帮助页或新的登录方式。
- 不重设计已登录账户页、主导航、应用顶栏或全局主题。
- 不改变手势模板筛选、下载、详情或采纳逻辑。
