# 删除暂停命令与独立可重复修饰符设计

日期: 2026-08-03

## 范围

本次包含两项相互关联的配置与手势运行时变更:

1. 从命令类型中删除 `pause`,并删除只服务于该命令的执行与界面代码。
2. 为普通手势动作增加一个独立修饰符选择器。基础手势匹配后,所选修饰符每触发一次都立即执行一次命令,手势保持活动直到触发键释放。

托盘暂停、暂停快捷键、左键 + 中键和弦、暂停状态、暂停事件和本机暂停设置不属于删除范围。

## 术语与产品语义

**独立修饰符 (Gesture Modifier)** 是普通手势动作的独立匹配维度,可选值为无、滚轮向前、滚轮向后、左键、中键、右键、X1 和 X2。它不属于基础有序输入序列。

动作唯一性由“触发键 + 基础有序输入 + 独立修饰符”共同决定:

- 修饰符为“无”时,触发键释放后按现有流程执行命令。
- 修饰符非“无”时,基础输入匹配后进入等待状态;每次收到相同修饰符就立即执行命令。
- 一次修饰符执行不结束手势,也不加入基础输入;继续按住触发键可重复触发。
- 触发键释放只结束手势和覆盖层,不再次执行修饰符动作。
- 与触发键相同的鼠标键无法作为修饰符,界面中禁用该选项。
- 未匹配任何独立修饰符动作的鼠标键或滚轮继续作为有序输入处理,保留现有组合手势能力。
- 独立修饰符与同一事件可完成的旧有序输入动作发生竞争时,显式的独立修饰符动作优先。
- 保留现有滚轮 100ms 节流,防止高频设备造成无界命令洪泛。

## 配置协议 v5

配置格式从 v4 升级到 v5。

- `GestureSpec.modifier` 从旧配置兼容字段改为 v5 的独立修饰符字段。
- 删除 `GestureIntent.executeOnModifier`;非空修饰符天然表示立即且可重复执行。
- `GestureSpec.inputs` 继续保存基础有序输入,以兼容按钮、滚轮和笔画混合序列。
- 从 `Command` 联合类型删除 `{ type: "pause" }`,命令类型数量由 12 个变为 11 个。

### v1-v4 迁移

旧版本需要同时考虑 `modifier` 和 `executeOnModifier`,不能把所有旧 modifier 直接解释为 v5 独立修饰符:

1. 先取得旧版有效输入:若 `inputs` 已存在则使用它,否则把 `strokes + modifier` 转换为有序输入。
2. 若 `executeOnModifier == true` 且有效输入的最后一步是鼠标键或滚轮,把该末步移出基础输入并转换为 v5 独立修饰符。该动作保持立即执行,并获得新的重复触发能力。
3. 其他动作原样保留完整有效输入,并把 v5 `modifier` 设置为 `none`。
4. 删除 `executeOnModifier`。
5. 递归把全局动作、应用动作、边角动作和旧边角命令图中的 `pause` 命令替换为 `doNothing`。
6. 写入 `formatVersion: 5`。

shared 和 Rust 本地加载边界必须执行等价迁移。Rust 在反序列化当前 `Command` 前先处理中性化,避免一条旧命令使整份配置回退为默认值。WGestures 导入遇到暂停命令时同样降级为“什么也不做”。

## Rust 运行时

`IntentFinder` 分离两种查找:

- 普通完成查找只返回 `modifier == None` 且基础输入完全匹配的动作。
- 修饰符查找按触发键、当前基础输入、独立修饰符和应用作用域精确匹配。

收到 `ModifierFired` 时按以下顺序处理:

1. 用当前基础输入尝试独立修饰符查找。
2. 命中时立即发送该意图,不修改基础输入,因此下一次相同修饰符仍能命中。
3. 未命中时把事件追加到基础有序输入,继续现有组合手势匹配。

删除 `executedOnModifier`/`executed_on_modifier` 状态。PathEnd 的普通查找不会返回带独立修饰符的动作,因此不存在释放时二次执行。

普通命令每次修饰符事件执行一次。Node 插件第一次命中时调用 `gestureRecognized` 和 `modifierTriggered`,后续重复命中继续调用 `modifierTriggered`,触发键释放时调用 `gestureEnded`;有界非阻塞队列和每插件串行约束不变。

从 Rust `Command`、Windows/macOS 命令分发和 `execute_intent` 删除 Pause 命令分支。全局暂停状态机及其托盘、快捷键、和弦入口保持原样。

## Desktop UI

普通手势编辑器删除“最后一个按键触发时立即执行”开关,改为“修饰符”下拉选择器:

- 选项:无、滚轮向前、滚轮向后、左键、中键、右键、X1、X2。
- 与当前触发键相同的鼠标键选项禁用。
- 标签旁使用问号图标和 tooltip。中文文案为“修饰符触发立刻执行同时继续监听修饰符是否触发”,英文提供等义翻译。
- 重新录制基础手势时保留当前独立修饰符。
- 助记符和重复检查同时包含独立修饰符。

命令编辑器、命令工具函数、浏览器 mock、中文/英文文案和 Web Console 删除 Pause 命令展示。暂停设置页、托盘状态和暂停快捷键界面保持不变。

界面沿用现有紧凑工作台布局,使用菜单型选择器和图标 tooltip;最小 `800x560` 视口不得产生横向溢出。

## 测试与验收

### Shared

- v1-v4 普通旧 modifier 保留为 inputs;旧立即执行动作的末尾按钮/滚轮迁移为 v5 独立 modifier。
- 所有配置作用域中的 Pause 命令稳定迁移为 DoNothing。
- v5 schema 拒绝 Pause,迁移及解析输出不再保留 executeOnModifier。
- 动作唯一性包含独立修饰符。

### Desktop Rust

- 普通动作与独立修饰符动作分开匹配,应用覆盖和全局继承规则保持不变。
- 右键 + 滚轮向后可在同一次按住期间重复执行,每次命中不增长基础输入。
- 未命中的滚轮/鼠标键仍进入有序输入。
- 修饰符动作释放时不二次执行。
- Node 插件重复触发保持 lifecycle 顺序和有界队列边界。
- 旧 Pause 配置加载后只中性化该命令,不重置其他设置。

### Desktop Vue 与消费者

- 下拉选项、同触发键禁用、重新录制保留、tooltip 和中英文文案测试。
- 删除 Pause 命令选项和描述。
- shared、Desktop、Server、Web Console 编译及 API 漂移检查通过。
- 浏览器 preview 在中文/英文和 `800x560` 下检查选择器、tooltip、文本适配和横向溢出。

Windows 与 macOS 共用平台无关 matcher/runtime 语义和各自现有钩子输入。Windows 运行时实测应覆盖滚轮重复执行;macOS 真机输入观察继续按现有 M4 `DEFERRED (owner-approved)` 清单记录,不能用 Windows 或单元测试冒充已通过。

## 非目标

- 不删除全局暂停能力或其任何非命令入口。
- 不改变基础有序输入最多 12 步、方向解析、点击透传、覆盖层实现或滚轮节流。
- 不给边角动作增加独立修饰符;边角动作继续使用现有边角序列。
- 不改变 Node 插件 API 或宿主安全边界。
