# 音量命令最终状态覆盖层反馈设计

## 状态

已确认设计，待实施。

## 背景

GodGesture 已经通过原生覆盖层在手势识别期间显示匹配到的手势名称。音量控制命令目前可以调整系统默认输出设备的音量，但命令完成后没有反馈最终音量。用户需要看到命令实际生效后的最终音量；静音状态需要显示“静音”。

当前 Windows 和 macOS 各自维护一份 `OverlayCmd` 定义，调用层直接依赖当前平台模块。若为音量反馈继续分别扩展平台枚举，会让新的提示类型重复进入两个平台模块，增加后续维护成本。

## 目标

- 音量控制命令成功后显示系统实际最终状态。
- 非静音状态显示整数百分比，例如 `0%`、`50%`、`100%`。
- 静音状态在中文界面显示“静音”，英文界面显示 `Muted`。
- 普通路径手势、修饰手势、触发角和摩擦边的音量命令都显示反馈。
- 复用现有原生覆盖层的标签绘制、位置、淡出和窗口行为。
- 提供平台无关的覆盖层反馈 API，让调用方只实现一次。
- 遵循现有“显示命令提示”设置和 `preferences.locale`。
- Windows 与 macOS 保持相同的用户可见语义。

## 非目标

- 不改变音量命令的增量语义、滚轮方向语义或静音切换语义。
- 不实现新的前端 Toast 或 WebView 覆盖层。
- 不替换现有手势名称提示的视觉样式。
- 不显示配置推算值；平台状态读取失败时不猜测最终音量。
- 不扩展系统混音器或应用级音量控制。

## 用户可见行为

1. 命令类型为音量控制时，命令执行器先完成系统音量调整。
2. 命令执行器读取调整后的默认输出设备状态。
3. 读取到未静音状态时，原生覆盖层显示最终整数音量，例如 `42%`。
4. 读取到静音状态时，原生覆盖层显示本地化的“静音”或 `Muted`。
5. 反馈使用现有 `showCommandName` 设置；关闭该设置时，命令仍执行但不显示标签。
6. 反馈使用现有 `fadeOut` 设置。启用时按原生覆盖层现有淡出机制消失；关闭时遵循当前覆盖层的立即隐藏语义。
7. 音量命令执行失败或最终状态读取失败时记录错误，不显示旧值或推算值。

## 架构设计

### 1. 统一音量反馈状态

在引擎音量模块定义平台无关的最终状态类型，至少覆盖：

- `Muted`
- `Percent(u8)`

平台命令执行器在音量命令成功后返回该状态；其它命令返回无反馈结果。百分比在进入反馈层前限制到 `0..=100`，并按整数显示。

Windows 使用默认 `eRender/eMultimedia` endpoint：

- 调整音量后重新读取 `GetMute`。
- 未静音时读取 `GetMasterVolumeLevelScalar` 并转换为整数百分比。
- 静音切换后仍以最终 `GetMute` 结果为准。

macOS 使用一条 AppleScript 完成调整并读取 `get volume settings` 的最终 `output volume` 和 `output muted`；脚本输出由平台命令模块解析为统一状态。脚本失败或输出无法解析时返回错误。

### 2. 公共覆盖层反馈 API

新增平台无关的覆盖层公共模块，统一定义：

- `TrailColors`
- `OverlayCommand` 及其轨迹、识别、独立标签反馈、结束和取消命令
- 覆盖层发送接口或等价的 `OverlaySink` trait
- `show_label_feedback(...)` 公共辅助入口

独立标签反馈命令包含：

- 用于选择目标显示器的屏幕坐标
- 要显示的文本
- 是否淡出

`lib.rs` 的引擎消费线程和未来其它调用方只依赖公共 API，不直接引用 Windows/macOS 的命令枚举。Windows 与 macOS 的 `Overlay` 实现只负责：

- 原生窗口和线程/消息泵。
- 显示器表面或 CALayer 的创建。
- 平台对应的像素提交。
- 对公共命令执行同样的标签生命周期语义。

### 3. 独立标签反馈生命周期

独立标签反馈不复用“活动轨迹必须存在”的前置条件：

- 停止当前标签或轨迹的淡出计时。
- 清理旧轨迹点。
- 根据传入坐标确保目标显示器覆盖层存在。
- 设置标签文本、识别态和标签显示状态。
- 不绘制轨迹，只复用现有标签字体、背景、位置和像素绘制逻辑。
- 按 `fadeOut` 设置开始现有淡出或立即隐藏。

普通手势当前在执行命令前结束轨迹；音量命令执行成功后再调用公共标签反馈 API。触发角和摩擦边直接在统一命令执行返回后调用相同 API，因此四类入口不会分叉。

### 4. 引擎命令入口

`execute_intent` 或等价公共命令执行边界返回可选的音量反馈状态。各入口在执行成功后使用同一帮助函数发送提示：

- `ModifierFired`：使用当前手势上下文起点。
- `PathEnded`：使用当前手势上下文起点。
- `CornerEdgeFired`：使用触发角/摩擦边命令的 origin。

Node 插件和其它原生命令不产生音量反馈。音量状态格式化和“是否允许显示”判断集中在调用层公共函数，避免四处拼接文本。

### 5. 本地化

格式化函数接收当前配置中的 `Locale`：

- `zh-CN`：静音文本为“静音”。
- `en`：静音文本为 `Muted`。
- `auto`：使用当前平台系统语言解析结果。

数字百分比不依赖语言，统一使用 ASCII 数字和 `%`。本地化文本只在引擎反馈格式化边界生成一次，覆盖层只接收最终显示字符串，不读取 i18n、store 或配置对象。

## 错误与并发处理

- 音量设置成功但回读失败时，不发送反馈，避免显示不可信状态。
- 音量设置失败时保持现有命令错误日志行为，不影响覆盖层的轨迹结束和清理。
- 音量反馈发送在命令执行完成后进入现有覆盖层队列，遵循 FIFO；新反馈会停止旧淡出并替换旧标签。
- 反馈 API 不在钩子线程调用。所有音量系统调用、AppleScript 和覆盖层重活继续运行在引擎消费线程或覆盖层线程。
- 覆盖层反馈不获取焦点、不改变光标、不注入鼠标或键盘事件。

## 测试设计

### 引擎音量模块

- 验证 `Muted` 和百分比状态格式化为中英文文案。
- 验证百分比边界为 `0..=100`。
- 保留现有增量、滚轮方向、静音切换和目标音量计算测试。

### Windows 命令模块

- 用可测试的状态读取/转换逻辑覆盖音量调整后的最终主音量。
- 覆盖静音切换后状态读取。
- 覆盖设置失败和读取失败不返回反馈。

### macOS 命令模块

- 覆盖 AppleScript 最终状态输出的构造和解析。
- 覆盖静音与非静音输出。
- 覆盖脚本失败、空输出和非法输出不返回反馈。

### 原生覆盖层

- Windows/macOS 各自验证独立标签命令在没有活动轨迹时能够渲染。
- 验证新标签停止旧淡出并替换旧标签。
- 验证标签结束后不残留上一次文本。
- 验证原有手势名标签和轨迹命令行为不回归。

### 引擎消费线程

- 验证普通路径、修饰手势、触发角和摩擦边都走同一音量反馈入口。
- 验证非音量命令不发送音量标签。
- 验证关闭 `showCommandName` 时不发送反馈但仍执行命令。

## 验收标准

- Windows 真实设备执行音量上调、下调和静音手势，覆盖层显示实际最终百分比或“静音”。
- macOS 真实设备执行同样三类操作，显示语义与 Windows 一致。
- 四种命令入口均可触发反馈。
- 调整系统音量后手动改变系统状态，再次执行命令时提示仍以本次实际回读结果为准。
- 现有手势名提示、轨迹、淡出和显示命令提示开关通过回归测试。
- Desktop Rust 测试、Desktop 前端测试、类型检查和差异检查通过。
