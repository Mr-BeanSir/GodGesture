# 手势移动后的右键消费与轨迹收尾设计

日期: 2026-08-03

## 问题

触发键按下后，移动超过 `initialValidMovePx` 会进入轨迹显示状态；但如果移动尚未形成一笔，释放时仍会合成原始点击。该分支没有发送路径结束或取消消息，导致轨迹残留，同时目标应用收到不应出现的原始右键。

## 目标语义

- `Pending` 表示仍可能是普通点击。触发键在该状态释放时，合成一次原始点击。
- 移动达到 `initialValidMovePx`、收到附加鼠标键或收到滚轮后进入 `Tracking`，表示本次触发键已经被手势捕获。
- `Tracking` 状态释放触发键时始终产生 `PathEnd`，不再根据是否已形成笔画决定透传点击。
- `PathEnd` 必须进入统一覆盖层收尾流程。无匹配手势时只清除或按配置淡出轨迹，不执行命令，也不合成原始点击。
- Windows 与 macOS 共用平台无关的 `PathTracker` 语义；平台钩子和原生覆盖层协议不变。

## 方案比较

1. 推荐：收紧状态语义。只允许 `Pending` 合成点击，`Tracking` 始终结束手势。改动集中，直接表达产品规则。
2. 在释放时检查 session 是否已有视觉点。会让 tracker 依赖 runtime 的渲染细节，状态边界不清晰。
3. 给 `Tracking` 增加 `moved` 标志。能够表达移动，但附加按键和滚轮仍需额外分支，产生无必要状态。

采用方案 1。

## 实现范围

- 修改 `engine/tracker.rs` 的触发键释放分支，删除“Tracking 但没有笔画则合成点击”的行为。
- 更新 tracker 单元测试，覆盖超过起始阈值但未形成笔画时返回 `PathEnd`。
- 增加 runtime 回归测试，验证该路径发送 `PathEnded` 且不调用 `synthesize_click`。
- 更新 `docs/PROJECT_STATUS.md`，记录新的点击消费边界与验证结果。

## 验证

- 触发键按下后未达到阈值，释放仍合成原始点击。
- 多次小步折返但累计过程从未越过阈值，仍视为普通点击。
- 任一时刻与起点距离达到 `initialValidMovePx` 后，即使未形成笔画，释放也结束轨迹、不合成点击。
- 已识别和未识别手势均通过统一 `PathEnd` 收尾；无匹配意图不执行命令。
- 运行 Desktop Rust library 定向测试、全库 library 测试、严格 Clippy 和实际修改文件的 rustfmt。

## 非目标

- 不调整 `initialValidMovePx` 默认值或配置协议。
- 不调整笔画识别阈值、方向解析、淡出动画或覆盖层渲染实现。
- 不改变起始停留超时转普通拖拽的现有行为。
