# 同步冲突模型:整库版本化 + 后写胜出 + 服务端快照兑底

用户配置(手势库/应用/触发角/偏好)作为一个带单调递增版本号的整体文档同步。客户端推送时携带其基准版本号做乐观并发控制:服务端版本更新则拒绝,客户端先拉取最新再推送;后推送者整体覆盖。每次成功推送服务端保留历史快照,Web 控制台与桌面端可查看并回滚,兜住"后写覆盖丢改动"的罕见并发场景。

放弃实体级合并(按手势/应用粒度版本化 + 删除墓碑):实现复杂度高一个量级,而配置是低频修改、几十 KB 的小数据,双设备同时编辑罕见,同条目冲突最终仍需后写胜出,收益不成比例。放弃冲突弹窗:对低频冲突场景打断感大于价值。

同步文档按 UTF-8 JSON 序列化后不得超过 4 MiB，服务端在进入写事务前再次校验并以 413 拒绝，不截断。Node 插件源码、manifest、lockfile、依赖和在线来源不在同步文档中，手势命令只保存 `pluginId`。快照同时受“最新 100 个”和“每用户历史正文 64 MiB”约束,每次推进版本后按新到旧累计并裁剪,始终保留最新快照。数量与总字节必须共同评估,避免配置正文把快照存储放大到无界。
