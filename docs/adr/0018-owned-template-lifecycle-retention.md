# 作者模板生命周期与版本保留策略

## 状态

已采纳（2026-08-14）；本 ADR 取代 ADR-0014 中“作者撤回不删除历史版本或对象”的长期保留部分，
不改变模板版本不可变、Server 管理公共目录、管理员审核和 RustFS 对象由 Server 保存的结论。

## 背景

GodGesture 已支持用户把本地手势模板提交到官方 Server 审核。原有协议只覆盖投稿、审核和作者撤回，
没有为作者提供“我提交的模板”管理入口，也没有规定投稿版本的长期上限。模板版本无限增长会增加
PostgreSQL 审核元数据和 RustFS 不可变对象的存储成本；作者也需要清理被驳回或已撤回的模板族。

## 决策

- Server 提供认证的作者模板列表。列表以模板父 ID 分组，返回父状态以及按版本号倒序排列的版本摘要。
- 同一模板的每次修改仍然创建新的不可变版本。被驳回和已撤回的模板可以再次提交新的版本；该版本仍需重新审核。
- 更新版本可以独立修改标题、标签和摘要；这些元数据只属于新版本，待审核期间不覆盖当前公开版本，通过后随
  最高已发布版本一起进入公共目录。
- 管理员暂停和恢复作用于模板父 ID，而不是某一个版本：暂停不回退、不修改版本状态，恢复后重新公开该族最高
  的已发布版本。作者在父模板暂停期间不能通过投稿绕过管理员发布闸门。
- 作者撤回只允许作用于至少存在一个 `published` 版本的模板族。撤回将该模板族中仍可由作者撤回的
  `pending_review`、`published` 和 `rejected` 版本转为 `withdrawn`，公共目录依据版本状态立即不再展示。
  `suspended` 版本由管理员治理，不被作者覆盖；撤回也不会清除父模板的
  `publicationSuspendedAt`，管理员必须执行恢复才能解除模板族暂停。
- 作者删除只允许作用于不含 `published`、`pending_review` 或 `suspended` 版本的模板族，即被驳回或已
  撤回的模板。删除会移除该模板族的数据库记录、关联审核/举报/下载元数据和 RustFS 对象；拥有发布版本、
  待审核版本或管理员下架版本时，Server 拒绝删除。
- 每个模板族只保留版本号最大的 50 个版本。创建新版本的事务锁定父模板行，插入成功后删除超出 50 个的
  旧版本及其关联元数据；事务提交后再尽力删除对应 RustFS 对象。数据库版本记录是可见性事实来源，
  对象清理失败不能回滚已经成功提交的版本写入。
- 作者管理接口不允许编辑已投稿内容。Web Console 只提供状态、版本摘要、撤回和合法删除操作；
  Desktop 投稿向导负责选择本地包并向新模板或已有模板提交新版本。

## API 边界

- `GET /public/templates/mine`：认证读取当前账户拥有的模板族和最多 50 个版本摘要。
- `POST /public/templates`：提交新的模板族。
- `POST /public/templates/{id}/versions`：向当前账户拥有的模板族提交不可变新版本。
- `POST /templates/{id}/withdraw`：作者撤回已发布模板族；非法状态返回业务错误。
- `DELETE /templates/{id}`：作者删除仅包含被驳回/已撤回版本的模板族。

所有接口继续使用 JWT、邮箱验证和现有模板配额。作者 ID 由令牌取得，不接受客户端传入。

## 后果

模板审核历史不再无限期保留：超过最新 50 个版本的旧版本及其关联元数据会被清理。管理员审计日志仍保留
操作主体和模板/版本 UUID 元数据，但不保证 UUID 对应的旧版本正文继续存在。RustFS 清理采用提交后补偿，
因此短时间内可能存在孤立对象，后续清理任务可以按对象键扫描处理。
