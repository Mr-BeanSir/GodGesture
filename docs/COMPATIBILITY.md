# 兼容代码登记

本文档是项目中仍然保留的兼容代码唯一登记表。它不记录普通的现行协议字段、
平台 API 适配、生成代码或测试夹具；只有为了让旧版 GodGesture 代码、旧调用方
或旧持久化格式继续工作而保留的分支、参数、字段、类型和转换逻辑才需要登记。

兼容代码在源代码附近使用对应的 `COMPAT-*` ID。登记项只保留仍存在的代码，
不建立“已删除”历史条目；删除代码时必须在同一变更中删除对应记录，git 历史
负责保留审计痕迹。

## 登记要求

新增或决定继续保留兼容代码时，必须填写以下信息：

- 唯一 `COMPAT-*` ID，以及源代码附近的同一 ID；
- 登记时仓库当前版本；
- 登记日期、时间和时区，统一使用 `YYYY-MM-DD HH:mm:ss ±HH:mm`；
- 代码文件和符号/分支位置；
- 兼容的旧合同、保留原因和明确的删除条件；
- 最近一次 release 复核的版本、日期时间和用户决定。

登记版本是写入登记时的当前版本，不得用未来版本代填。兼容项继续保留时，
每次 release 复核后更新“最近复核”字段。

## Release 闸门

每个版本 release（稳定版和 prerelease 都包括）在创建版本提交或 tag 前，必须
读取本表并逐条询问维护者/用户：

> `COMPAT-*` 这项兼容代码在目标版本中继续保留，还是现在删除？

没有明确决定的条目不得进入 release。用户选择继续保留时，更新该条目的最近
复核版本、日期时间和决定；用户确认删除时，先删除代码及测试，再在同一变更中
删除本表对应条目和源代码 ID，并搜索确认旧合同和 ID 不再残留。删除后的条目
不得保留为 `removed` 或 `pending` 状态，这样后续 release 不会重复处理同一删除。
